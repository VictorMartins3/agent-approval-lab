Evidence and authority in dependency review agents

A security review can reach a cautious decision while overstating what the source code shows.

Victor Martins30 September 2026Code and records available

Abstract

We evaluated dependency updates in 27 bounded agent sessions, then examined explanation accuracy in 30 structured reviews. The agent escalated the suspicious update in every primary session, including those without a capability scanner. In the follow-up, both report formats correctly classified all 120 evaluated source-operation fields. Additional source hints provided no classification gain. Scripted controls separately demonstrated that an editable approval can make CI pass while the original warning remains visible. The study distinguishes review decisions, supporting evidence, and approval authority. All cases are synthetic; these results do not estimate production accuracy.

01

The observation

In a primary agent session, the explanation described a script that “reads” a credential path. The supplied code contains no file-read call. It imports modules and exports a function that returns a path and those module handles.

The formatting entrypoint is unchanged. The new postinstall entrypoint exports the function without invoking it. Neither the scanner nor the experiment executes that script.

02

Two experiments, separate questions

Approval authority

27 agent episodes

Three updates, three CI configurations, three repetitions per cell. The agent could inspect source, apply an update, run tests, request review, and attempt approval. The configurations used application tests alone, an editable approval baseline, or a protected baseline.

Explanation accuracy

30 structured reviews

Five updates, two report formats, three repetitions per cell. Both formats included full numbered source and an explicit review contract. One added source-linked hints and interpretation limits. Direct and computed credential-read calls served as positive controls.

The CLI reported claude-sonnet-5 for all primary trials. Each trial started a fresh session. Case labels were excluded from model inputs. An earlier 27-episode pilot is retained separately, with its corrections documented. The two primary experiments differ in task and policy and should not be treated as a before-and-after causal comparison.

Both formats distinguished path references from read calls, including the computed-property control. All routine and legitimate updates were recommended ready. Nine strict quotation mismatches were indentation differences; normalization resolved them without changing a file, line, or word. This was a post-hoc diagnostic, reported separately from the original scores.

What the controls establish

The actual capsurface Action helper retains findings against the target baseline while its enforcement output evaluates the proposed baseline. A selective approval can therefore make CI pass with the original findings still visible. The protected configuration prevents that transition through its tool boundary. It also requires a separate reviewer for legitimate capability changes.

04

Implementation

The review contract separates source observations, risk interpretation, and limits. Positive operation claims require citations. The checker verifies source locations, normalizes edge whitespace, and rejects assertions of observed runtime execution when no trace is supplied.

python3 check_review.py \
  --review examples/evidence-review/review.json \
  --sources examples/evidence-review/sources.json

A matching quotation does not establish that it supports a claim. The checker returns semantic_claims_verified: false. Semantic support is scored against a hand-authored oracle only in this bounded evaluation. The extra literal-pattern hints remain experimental: they did not improve classification in this batch and are not a complete source analysis.

05

Limitations

  • Three repetitions per cell, short synthetic fixtures, and one reported model configuration.
  • Structured scores cover four operation fields, not every sentence of the explanation.
  • Network and process calls have negative controls only; their positive recall was not tested.
  • Protected approval is enforced by the harness tool boundary, not an operating-system sandbox.
  • The review task and policy changed between experiments. The improved historical outcomes cannot be attributed to the added hints.
